## Findings and fixes

The initial run (1366×900) found one failing rule, `color-contrast` (WCAG 1.4.3,
serious), only in the **light** theme. Dark mode was clean. Manual checks of axe's
"needs review" items found two more contrast failures that axe could not measure.

| # | Element | Before | After | Fix |
|---|---|---|---|---|
| 1 | Emerald badges ("Balanced", "Completed") — Dataset list, Runs table | 3.40:1 (`#059467` on `#d1fae5`) | 4.9:1 | `--accent-emerald-foreground` 30% → 24% lightness |
| 2 | Orange "classical" badge — Runs table | 3.12:1 (`#e9590c` on `#ffedd6`) | 4.9:1 | `--accent-orange-foreground` 48% → 37% |
| 3 | Destructive badge — Dataset list | 3.98:1 (`#e7000b` on `#fde5e7`) | 4.85:1 | Light mode uses `text-accent-red-foreground` (red 51% → 45%) in `components/ui/badge.tsx` |
| 4 | Muted text on `bg-muted` — Optimizer header chips | 4.34:1 (`#737373` on `#f5f5f5`) | 5.5:1 | `--muted-foreground` `oklch(0.556 0 0)` → `oklch(0.5 0 0)` |
| 5 | "When to use" field help — Settings | 3.23:1 (`#8f8f8f` on `#fff`) | 6.0:1 | Dropped `text-muted-foreground/80` in `app/settings/page.tsx` |
| 6 | "Open the Optimizer" gradient card — `/` (manual) | 3.26:1 light / 3.76:1 dark at the gradient end | 4.75:1 / 5.42:1 | Gradient end `to-brand/70` → `to-brand/90` in `app/page.tsx` |
| 7 | History count in the Report tabs — `/preview-report` (manual) | ≈2.8:1 light / ≈3.6:1 dark (`opacity-70` on already-muted text) | ≥5:1 | Removed `opacity-70` in `components/optimizer/steps/ReportStep.tsx` |

Preventive (not flagged, but within 0.05 of the 4.5:1 limit on their tinted badge
backgrounds): `--accent-amber-foreground` 37% → 36% and `--accent-purple-foreground`
56% → 54%.

Side effect: the chart series colours `--chart-1` (purple) and `--chart-2` (orange) are
derived from these tokens, so quantum/classical series are slightly darker in light mode.

All changes are in `frontend/app/globals.css` (light `:root` block only), plus the three
component files named above.

## "Needs review" items after the fixes

| Page | Items | Resolution |
|---|---|---|
| `/runs` | 11 table cells in rows 11–13 (1366×900 only) | Below the fold, so axe could not sample their background. They disappear in the 1366×2400 pass, where the same cells pass `color-contrast`. |
| `/` | "+20 more" link (1366×900 only) | Same below-the-fold artefact; passes at 1366×2400. |
| `/` | Heading and body text on the gradient card (both viewports) | axe cannot measure text on gradients. Computed by hand at both gradient stops: ≥4.75:1 light, ≥5.42:1 dark (fix #6). |

## Not covered

- Optimizer steps after Dataset (Features, Configure, Optimize, Analyze, Report as a live
  step), dialogs, toasts, and error states — they need a dataset loaded and an interactive walk-through.
- The login screen shown when Auth0 is configured (the audit ran with `AUTH0_*` unset).
- The docs site (`docs-site/`).
- Anything automated tools cannot judge: keyboard-only operation and focus order, screen
  reader announcements, reflow at 320 CSS px / 400% zoom, motion, and meaningful
  alt text. axe-core typically detects roughly a third of WCAG issues; a manual pass is
  still required for a conformance claim.

## Reproducing

1. Start the backend with auth disabled so pages render without logging in:
   `AUTH0_DOMAIN= AUTH0_CLIENT_ID= AUTH0_CLIENT_SECRET= AUTH0_SECRET= uv run uvicorn quoptuna.server.main:app --port 8000`
2. Start the frontend: `cd frontend && npx next dev -p 3000`.
3. For each page and theme (`localStorage.setItem('theme', 'light' | 'dark')`, then reload),
   inject `axe-core/axe.min.js` and run:

   ```js
   await axe.run(document, {
     runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'] },
   });
   ```

   Run at 1366×900 and again at 1366×2400.
